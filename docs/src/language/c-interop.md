# C Interop

Helix calls C directly and can be called from C, with the C calling convention of each target.
`helix translate-c` turns a C header into Helix declarations.

## Calling C

```hx
extern "C" function strlen(text: readonly u8[*]): usize;
extern "C" function printf(format: readonly u8[*], ...): i32;

export function main(): void {
    println(strlen("hello"));                   // 5
    void printf("%d + %d = %d\n", 2, 3, 5);     // 2 + 3 = 5
}
```

- A string literal converts to the NUL-terminated `readonly u8[*]` that C expects.
- `void` drops the result of `printf`, since Helix doesn't let a result go unused.
- `...` makes a C function variadic.

## Being called from C

```hx
export extern "C" function hx_add(a: i32, b: i32): i32 {   // the C symbol hx_add
    return a + b;
}
```

## C declarations

```hx
extern "C" struct Timespec { sec: i64, nsec: i64 }          // C layout

extern "C" let optind: i32;                                 // a C global that Helix reads and writes
extern "C" const environ_size: usize;                       // a C global that Helix only reads

// a C function pointer: called with the C convention, and it may be variadic
type Compare = ?extern "C" (a: ?readonly u8[*], b: ?readonly u8[*]) => i32;
type Logger = ?extern "C" (format: readonly u8[*], ...) => i32;
```

Another module's `let` global, a C global among them, can be assigned through its namespace:

```hx
import * as c from "./c";

c.counter += 1;
```

Structs passed to or returned from `extern "C"` functions by value follow the target's C rules
(aarch64, x86-64 System V, Windows x64, and wasm32), in every direction:
Helix calling C, C calling Helix, and calls through C function pointers.

## Callbacks

A named Helix function converts to a C function type, so it can be a C callback:

```hx
extern "C" function qsort(base: u8[*], count: usize, size: usize, compare: (a: readonly u8[*], b: readonly u8[*]) => i32): void;

function compareI32(a: readonly u8[*], b: readonly u8[*]): i32 {
    unsafe { // [!code focus:5]
        const x = @ptrCast(readonly *i32, a);
        const y = @ptrCast(readonly *i32, b);
        return *x < *y ? -1 : *x > *y ? 1 : 0;
    }
}

export function main(): void {
    let numbers: i32[5] = [5, 1, 4, 2, 3];
    unsafe {
        qsort(@ptrCast(u8[*], &numbers), numbers.len, @sizeOf(i32), compareI32);
    }
    println(numbers);                                   // [1, 2, 3, 4, 5]
}
```

A Helix function whose signature passes structs by value gets a C entry point of its own when it becomes a callback.
A function pointer held in a variable has no function to give an entry point to,
so it converts only when nothing in its signature differs between Helix and C.
Only C function types can be variadic, and the address of an `extern "C"` function has its C function type.

## unsafe

Raw pointers, `T[*]`, carry no length, so nothing checks an index into them.
Indexing one, pointer arithmetic, and `@ptrCast` are only allowed inside `unsafe { }`, which keeps them easy to find
and review:

```hx
function first(bytes: readonly u8[*]): u8 {
    return bytes[0];                        // outside unsafe // [!code --]
    unsafe { return bytes[0]; } // [!code ++]
}
```

```text
error: indexing a raw `u8[*]` pointer needs `unsafe { }`
  = hint: nothing checks the bounds of a raw pointer; prefer a slice, or wrap this in `unsafe`
```

`&x` and `&array` convert to a raw pointer without a cast, at the same address.
A slice converts with `.ptr`, so dropping its length is visible.

## translate-c

`helix translate-c` reads a header with libclang and writes Helix declarations, which you commit and review:

```bash
helix translate-c point.h -o src/point.hx
```

::: code-group
```c [point.h]
#include <stddef.h>
/** Adds two numbers. */
int add(int a, int b);
struct point { int x, y; };
typedef unsigned int uInt;
enum color { RED, GREEN = 5 };
#define VERSION "1.2"
size_t length(const char *s);
```
```hx [src/point.hx]
// Generated by `helix translate-c point.h`.
// Regenerate it rather than editing it; wrap it in a Helix API in another file.

export const VERSION = "1.2";
/** Adds two numbers. */
export extern "C" function add(a: i32, b: i32): i32;

export extern "C" struct point {
    x: i32,
    y: i32,
}

export type uInt = u32;

export type color = u32;
export const RED: color = 0;
export const GREEN: color = 5;

export extern "C" function length(s: ?readonly u8[*]): usize;
```
:::

::: tip 📝 Commit the output
The translation is an ordinary file that you review and commit, so a header change shows up as a diff.
Wrap the raw declarations in a Helix API in another file: errors instead of return codes, and slices instead of a
pointer and a length.
:::

| C                                                | Helix                                                            |
|--------------------------------------------------|------------------------------------------------------------------|
| `int f(const char *s, ...);`                     | `export extern "C" function f(s: ?readonly u8[*], ...): i32;`    |
| `struct handle;`, never defined                  | `export extern "C" struct handle {}`, used only through pointers |
| `typedef int (*cb)(int);`                        | `export type cb = ?(a0: i32) => i32;`                            |
| `enum color { RED };`                            | `export type color = u32;` and `export const RED: color = 0;`    |
| `T *`, `void *`                                  | `?*T`, `?u8[*]`, and `const` becomes `readonly`                  |
| `size_t`, `uint32_t`, `bool`                     | `usize`, `u32`, `bool`                                           |
| a union, a struct with bit fields                | a struct with only its size and alignment: `_bytes: u32[2]`      |
| `struct { int a; } inner;` inside `struct outer` | a struct of its own, `outer_inner`                               |
| `int v[]` as a parameter                         | `?i32[*]`                                                        |
| `#define MAX 64`, `0x1.0p-1`, `'A'`              | `export const MAX = 64;`, `0.5`, `65`                            |
| `struct stat` next to `stat()`                   | `struct_stat`, so the two names don't clash                      |

- It translates the header and the headers it includes from its own folder.
  `--dir` takes every header under the folder, and `--all` everything clang saw.
- `-I`, `-D`, and other clang options pass through, and `--target` sizes `long` for that target.
- What Helix can't express is left out with a comment that says why:
  `long double`, `_Float16`, SIMD vectors, Apple blocks, `static` and `inline` functions, `static` and thread-local
  variables, functions without a prototype, and names that are Helix keywords.
  Function-like macros are left out too.

`helix translate-svd` does the same for a microcontroller's registers.
See [Targets](/projects/targets#microcontrollers).

## C sources in a project

A package lists its C files in `helix.jsonc`, and `build.hx` can add more.
The compiler builds them with its own clang for whatever target the program is built for.

::: info 🧱 C for packages, not a C build tool
Helix compiles C so that packages can wrap C libraries and still cross-compile.
It doesn't run C build systems such as Make or CMake, and it doesn't compile C++.
:::
See [helix.jsonc](/projects/manifest#c) and [build.hx](/projects/build).
